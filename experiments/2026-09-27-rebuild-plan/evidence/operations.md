# operations: Operations, verification speed, and the mechanics of a safe wipe (C:/DEV/LitHarness to lightweight rebuild)

Edits and checks are slow for three measured reasons: the amount of code, checks that tie code to prose, and tests for one-off research. The suite has 6,022 tests (up from 3,763 on 09-03). Local handoff runs take 105–215 s, and 717 s under contention. The Windows CI jobs take 10–13.6 min against 2.5–4.8 min on Ubuntu. 9 of the last 20 CI runs were cancelled because pushes arrived faster than CI could finish. The slowest single test (45–59 s) checks that every symbol named in prose still exists. The stage-0 ledger cites 410 test names, which freezes those tests. 119 test files (32k lines) only exercise research scripts. Recent CI failures came from tests that pin prompt bytes.

A safe wipe is possible without force-pushing:
- origin/main already equals main at 40f58a2.
- There are no tags, stashes, hooks or branch protection.
- Only one commit exists solely on this machine: c8ef116 on claude/ox-alpha-trial-7f3a21.

Recommended route: tag and push a legacy ref, then delete through an ordinary commit on main. This keeps history and the memory directory keyed to C:/DEV/LitHarness. The dangers sit outside git:
- Another session holds uncommitted work in the primary tree (a produce.py one-command runner, atomic job recovery, `why --html`).
- A live litharness-mcp process holds .venv and litharness.db.
- About 2.3 GB of ignored third-party prose lives under research/. In this public repo it could be committed by accident once .gitignore is replaced.
- runs/ is 12 GB.
- 52 of 69 memory notes cite incumbent paths.
- The two skills, the workflow and .mcp.json all call the incumbent CLI.

Transport hardening must survive as one shared function per CLI. Today it is copied across 23 call sites and has drifted: covers.py lacks the Codex isolation flags, and providers/cli.py does not strip GIT_* variables.

Realistic targets for a small standard-library codebase:
- Full suite in 5 s or less in a single process, with no xdist.
- Lint and types in about 10 s.
- CI under 2 min with one Ubuntu job and one Windows job. Measured setup overhead is about 10 s on Ubuntu and about 28 s on Windows.
- Live isolation canaries stay opt-in and run after each CLI upgrade.
