# Planning material: separate developments, staging and placement

Read BRIEF.md, EPISTEMIC_GOVERNANCE.md and the source workflow RUNBOOKs under
experience-workflow-20260915 and chapter-coverage-20260915. The operator approved the
scene-numbering report's next step: an isolated reusable prototype, fresh concepts and
continuation. This is authoring research, not a reader measurement or production policy.

## Question and scope

Does a structured representation of generated arc developments, flexible staging and
tentative placement preserve the source story and change what outlines and chapters enact?
The numbered-input comparison is OBSERVED, not a causal premise or quality justification.
This trial jointly changes representation, paraphrases arc prose and adds planning guidance.
It cannot identify which component causes a contrast, or separate one draw from sampling.

Four paired source stories: two known cases (2 and 4, original racing and market concepts)
and two first-draw fresh concepts (1 and 3, inputs.json). No selection, replacement or redraw.
The fresh garden premise contains an explicit author requirement for the teacher to remain
physically absent for the first two chapters. This is a supplied story constraint, not a
generated suggestion to be rescheduled. Test scoped locks and actual promise dates offline too.

Both arms use source revision 80d37ba, halloran, third person, six one-scene chapters, and
1,400 target words per scene. A is the unchanged production outline input. B substitutes
structured planning material for only book_concept.first_arc.middle/closes and moves
generated debt due_scene values into a separate suggested-placement list. Original debt
subjects and owed text, turn and its horizon, experience brief, system, protagonist,
author wording, author locks, world, accepted history, actual open promises, output schema
and all other inputs remain unchanged. One first-arc rule is replaced with the versioned
material rule; the request profile identifies the research variant. Production source is
unchanged and imports no research code.

## Prototype and fidelity limits

One tool-free source transformation per case, before any new outline, receives the generated
arc's paragraph units and unchanged concept context. It returns developments, dependencies,
horizons, flexible staging and source-derived placement suggestions. No scores or candidate
preferences are requested. Its first output must validate or B stops without repair.

Code checks unique ids, source existence and coverage, dependency references/acyclicity,
placement references, and the exact source-concept hash. The material is tied to its first
raw receipt each time it is used. These checks cannot prove that a paraphrase preserves all
meaning or that a model classified a detail correctly. Full source/material reading after
generation must report omissions, new inventions and inappropriate demotions. Passing those
checks is not a validated quality signal or permission to deploy the converter.

The application renderer is wrapped before recording and dispatch. Every original outline
request must equal the sealed offline request. A passes through; B transforms only its
registered fields and rule. Saved concepts remain unchanged. No diagnostic notes or corpus
prose enter any request. Existing generated source material is the only transformation input.

## Limits and stop rules

120 provider calls including health probes; 2,000,000 recorded Usage.total tokens; 7,200
seconds after first dispatch; 30 calls per book; 20 ticks per phase. An admitted call can
cross a ceiling; report actual use. No fallback, reset, purchase, web search or publication.
Use the existing native gpt-6-astra/medium transport, ephemeral sessions, memory and project
instructions disabled. Only ordinary scoped world tools in seed/grow may run; the material,
outline and writing calls are tool-free. No live-provider test opt-in is set for checks.

A failed provider call, unknown usage, frozen-input mismatch or global ceiling stops calls.
Terminal jobs, operational exits, no_work before target or phase limits stop the affected
book; shared-source failure stops its pair. Material invalidity stops B and preserves A's
control. An unexpected outline input refuses before dispatch. Never silently resume an
interrupted run. Persist partial results and the cause, without replacement generation.
Release only this task's lock after work finishes.

## Readout and decision

Read narrative only once all books complete or stop. Read all source transformations, every
full outline, every reached chapter, retries and raw differences from accepted prose. Use
the CLI dossier skill to trace job-bound plans and full frozen writer inputs. Check source
fidelity separately from outline/writer fidelity; distinguish planned from enacted events.
Locate desire, activity, use/failure, consequence, personal response and next choice. Report
compression, omissions and useful contrary cases in either arm. For continuation check
changed circumstances, remaining constraints, new choices, and repetition of completed work.
Do not require every chapter to repeat a reward cycle or resolve future commitments early.

All request, transport, pairing, source, author-retention, volume and usage controls must be
reported, including failures and stops. If source conversion loses a commitment or violates

Keep concepts, source units, requests, prose, stores and detailed readings under ignored runs/.
