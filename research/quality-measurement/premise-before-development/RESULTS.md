# Premise before development: exploratory result

Both first-response generation trajectories completed. The initial public pursuit was
retained by the premise-first arm, but discovery introduced administrative scene business,
counted supplies and a new exclusion in the protagonist's motive. Concept development
strengthened the exclusion and the final listing repeated it. The original short premise
did not contain those additions. These are located observations, not a quality verdict
or evidence that the new procedure improves reader interest.

Precision also originated before expansion: the initial public premise already carried
a recurring exact interval and a childhood age. The editor removed the age from developed
material and left the interval. In the other arm, it removed decorative quantities while
preserving the counting mechanics invented by discovery. Editing local quantities does
not decide which invented mechanics or opening activity the story needed.

## Operational limit

The experimental runner reused production request renderers, parsers and precision edits,
but omitted the CLI coordinator's reserved-name check after discovery. Applying that
check afterwards shows the premise-first discovery would be refused before development.
Its later artifacts therefore do not constitute a successful production run. No production
guard was disabled. Preserve this omission; do not relabel the arm as passing end to end.

The two arms invented different stories, differ in call count and framing, and were run
in a fixed order. One control treatment was also inspected before its listing, departing
from the intended reading without prior source exposure. No causal ordering effect,
repeatability, reader appeal or Chapter 1 quality is established.

## Reproduction and disposition

The committed registration predates all live calls. Generated text, frozen runner,
requests, raw envelopes, exact edit proposals, comparison, inspection and validation
are under `runs/diagnostics/premise-before-development-20260908/`. The source-free
execution.json identifies those artifacts by hash. To repeat the offline checks:

```powershell
uv run python runs/diagnostics/premise-before-development-20260908/verify.py
```

All calls used subscription Claude Code with --safe-mode and empty tools. Frozen input
hashes and precision replay pass; existing book artifacts are unchanged. No model ranks
the outputs, no quality mechanism is qualified and no production change is adopted.

The next experiment should first enforce production-gate equivalence and hold one
starting premise fixed. Comparing openings generated directly from it with openings
generated after expansion would test transfer of the additions seen here. That is a
proposal, not a conclusion that a shorter input will solve chapter quality.
