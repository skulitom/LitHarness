# Automatic creative seeding experiment

The operator explicitly requested seeding by default and experiments on solutions. The
production change supplies a new random seed for each `concept` invocation, retains its
versioned creative brief, and preserves that input across development retries. Explicit
author directions take precedence. This is an authoring policy, not a qualified quality
metric, model selector or assertion of global originality.

## Comparison fixed before calls

Take three UUID seed labels once during preparation. Keep all three, without rerolling or
selecting their ingredients. Each uses index 0 of production `invention-seed.v1`. Make two
requests per seed with the production discovery renderer and identical original empty briefs:

Preparation may refresh the source snapshot after a pre-dispatch code correction, always
retaining the original three labels. Once progress exists, preparation refuses any refresh.

- **ingredients:** the five supplied ingredients only;
- **actions:** those same ingredients plus the activity-linked first magical success and
  further power growth used by the new production default.

Order: ingredients-0, actions-0, actions-1, ingredients-1, ingredients-2, actions-2. Each is
a fresh first response. The activity extension is derived from the opening activity, not
chosen by a model. No previous treatment, diagnostic description, recurring name or thematic
blacklist enters a prompt. The comparison is not matched for prompt length and tests these
authored inputs, not a general semantic-content effect.

After all six discovery calls, develop actions-0 and actions-2 with the production concept
renderer (six scenes, third person). Those positions are chosen now, before outputs. If
their discovery is invalid, skip the corresponding development without substitution.
Validate development with `Concept.from_development` and retain the result with its input
receipt. Do not run precision editing, listing, world creation or chapters, and do not
accept a plan into a book. These are pre-precision development artifacts, not production-ready
books. Do not read story outputs until the whole batch completes or an operational stop fires.

## Freeze and limits

Use committed source at the recorded base revision, overlaid with the four enumerated owned
production changes. Snapshot that source into the ignored run directory before dispatch;
unrelated uncommitted precision edits are not part of this experiment. Freeze the source,
runner, protocol, six prepared requests, seed receipts, dependency lock and Codex binary.
Commit source changes and registration before model calls. Import only the snapshot at run
time and verify it. Retain complete requests, full native receipts, outputs and validation.

Own runs/box.lock after checking processes. Run one sustained check or generation job at a
time. Use the same subscription Codex binary as the prior pilot, requested gpt-6-astra with
medium reasoning, no tools, fresh isolated sessions, no API keys or resets. Discovery asks
for 2,400 output tokens; development uses its production request limit. Each call has a
600-second timeout. Stop after eight attempts or 95,000 recorded tokens checked before a
dispatch; an in-flight call can exceed the token bound. Transport/auth/quota failure, unknown
usage or frozen-file drift stops the batch. No retries, fallback or implicit resume. Retain
recoverable usage from a failed native attempt separately. Never enable live-provider tests.

## Inspect and report

Use generation-trace comparisons to verify equal ingredients and matched system, schema,
parameters and native configuration within each discovery pair, with prompt additions
explicit. Read every full treatment and both attempted developments. Locate the first
reward, what the power actually does, what further growth does, and how these realize or
depart from each recorded seed. Report recurring rescue/repair structures, names, ignored
ingredients and mismatches; searches locate passages and do not classify stories.

Input adherence can support bounded implementation observations only. Do not assign quality
scores, rank candidates, claim distance from training data or infer a general success rate
from these three pairs. Development checks whether the supplied story persists through the
next stage, not whether a chapter will be good. Report failures and counterexamples equally.
The default is operator-authorized and is not selected by comparing model preferences.

Raw text and local receipts stay under runs/automatic-seeding-20260910. Commit code,
registration, hashes and bounded conclusions, not full generated prose.
