# lite: Lite prototype (C:/DEV/LitHarnessLite) and the retired first clean start (96ef4e2:clean_start/)

Lite is a 264-line runtime built only on Python's standard library: brief, then plan, then whole chapter. It lives in 4 local commits with NO git remote. Its Codex transport is the retired clean_start/codex_chapter.py flag set almost verbatim (96ef4e2), which makes it the only component that has survived two rewrites. On one matched brief it beat the incumbent's read-21/draw-6 chapter in both blinded orders, and all four controls passed. Lite used 2 calls and 15,904 tokens. The incumbent's chapter stage used 16 calls and 129,661 tokens (33 calls and 411,160 tokens for the full pipeline). Of those 33 calls, 11 are 'Reply with the single word OK.' health probes, including 8 of the 16 chapter-stage calls. The incumbent's real chapter work is 1 arc outline (73.6k chars), 4 per-scene drafts (30–48k chars each) and 3 scene compressions of about 60 words. Lite's draft request was 6.1k chars.

The first clean start (2026-09-08) was a single, unmatched sample that did not fix the operator's named defects. Its one real advantage, the Codex transport, was ported into the incumbent (c69e5ad, +2,439 lines), leaving it nothing unique. It was retired on 2026-09-09 (917ce1a) under 'one supported generation pipeline'. No stage-0 section records a fuller rationale. Afterwards the incumbent absorbed the lesson as patches and kept growing: over 18 days and 177 commits, tests grew +18.3k lines, research Python +35.3k and src +3.8k. The rebuild must replace the incumbent rather than feed it, must keep a standing matched evaluation harness, and must enforce budgets so per-defect rules do not regrow.

For a serial, Lite lacks canon/state, previous-chapter context, status and number tracking, continuity checks, Royal Road export, bounded retries and a Claude transport. It also has a Windows CRLF hash bug. The benchmark (swapped order, identical-text null, damaged control, quote grounding) is a good default skeleton, but it has several limits. It covers n=1 pair, uses the generator's own model as judge, damages text only loudly, has absolute scores that drift, and its rubric tells the judge not to reward system messages, which conflicts with the operator's LitRPG-furniture floor. As popcorn LitRPG, Lite wins on stakes, choice and hook, while Heavy wins on genre furniture (rank-ups), a relatable job-plus-hobby protagonist and levity. Lite's four retained defects become the first regression cases.

- [high] Half of the incumbent's chapter-stage calls are health probes. The real chapter work is 8 calls: 1 arc outline, 4 per-scene drafts and 3 'mechanical' scene compressions that exist only because scenes are drafted separately.

## Risks
- The single-pair win reverses on the next briefs. Clean start #1 was also one sample, and its standing collapsed when the sample did not hold. => Make the first milestone of the new repo a pre-registered replication on 3–5 new briefs against the frozen incumbent snapshot (runs/chapter-one/read-21/draw-6/source), using the generalized harness. Report within-pair contrasts and the order-agreement rate.
- Regrowth: each located defect (age, breath count, helmet) invites a new rule, validator or gate. This is the same pattern that produced 09-08's key-correction/command-cap/display-name patches and the post-retirement growth (tests +18k, research +35k lines in 18 days). => Set explicit CI budgets for runtime LOC, calls per chapter, tokens per chapter and test wall time. Admit a component only with a failing regression case plus a harness non-loss. Keep experiments in frozen per-date folders that production tests never import.
- Multi-chapter continuity is untested and is exactly where the incumbent's complexity (world graph, canon, extraction, repair) came from. The rebuild could reinvent it. => Start with a plain-text canon/state file plus the previous chapter (REPORT.md next step 2). Add structure only when R2/R3-class regressions (resource ledger, object continuity) fail across a 5–10 chapter run.
- The harness optimises away from the genre: the rubric discounts system messages, and the judge is the same model as the generator. => Add genre-function criteria (system furniture that moves, progress felt early, popcorn flow), a stat_flatten damage control, and a cross-family second judge.
- Evidence loss during the wipe: the Lite repo has no remote; saved books and runs/ live in the incumbent tree; the REPORT itself says not to delete the incumbent yet. => Before any wipe: push Lite to GitHub, tag the incumbent HEAD (archive branch/tag), exclude runs/ and *.db from the wipe, and record the tag in the new README.
- Windows CRLF translation breaks content-addressed receipts, and stale .running locks after a hard kill block resume. => Write bytes/newline='' and test artifact hash == receipt hash. Record the PID in the lock and verify the process is dead before clearing it (PowerShell by PID, per CLAUDE.md).
