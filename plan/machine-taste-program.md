# The machine-taste program: making the panel usable where human judgment is

**Status: adopted as the priority by operator directive, 2026-08-18.** This document is the plan
for the directive "research a solution to where machine panel taste can be used just as well as
human judgment." It supersedes nothing in the ledger; it *sequences* what the ledger already
concluded, and §82's standing rule is its first constraint rather than an obstacle it argues
with.

## 1. The goal, stated honestly

The target is a machine judge whose verdicts substitute for human reader judgment **in named
roles with named revocation conditions** — not a blanket equivalence, which §82 establishes no
machine-only evidence can ever certify. The program shape that follows from that constraint:

1. **Track A** — push panel quality as far as machine-side research can measure, against a fixed
   benchmark assembled from instruments this repo has already validated. Cheap, starts now.
2. **Track B** — buy one human anchor: the already-designed [reader-batch-1.md](reader-batch-1.md),
   whose second job is literally "anchor the machine panel" via a per-axis agreement matrix.
   Every paid judgment does double duty. Four-figure, operator-gated, starts the §59 clock.
3. **Licences** — convert the agreement matrix into scoped permissions (§5 below), each with a
   drift probe and an expiry, per §72's expires-on-use discipline.

**The economics that justify the program.** A panel comparison costs ~$0.05 and returns in
seconds (measured across §81/§83's runs); a paid human judgment is dollars and days. If a few
hundred human labels anchor a judge on even two or three axes, every subsequent evaluation on
those axes is ~100–1000x cheaper than the thing it substitutes for. That is the bet, and it is
falsifiable: Track A can fail to produce a candidate worth anchoring (§7).

## 3. Track A — judge engineering against a fixed benchmark

Assemble **JudgeBench** — one harness, five fixture families, run identically for every
candidate judge:

    B1  damage rungs        DEGRADERS at declared doses; pass = detect margin over sham
    B2  sham floor          rewhitespace + structure-preserving edits; pass = indifference
    B3  near-twins          §83's retells; pass = CALIBRATED INDIFFERENCE — a high honest
                            tie rate with bias in band. The §83 failure was forced choice
                            on unseparable pairs; a judge that knows what it cannot judge
                            passes, one that answers a side fails. This redefinition is the
                            single largest design change the program makes.
    B4  external label      rr_high vs rr_low conversion pairs; pass = ≥0.52 across strata
                            (§79's bar) with bias in band — the only axis where a human
                            outcome, not a human opinion, does the grading
    B5  named defects       certified repair pairs (em-dash, interiority) in the repair
                            direction; two-sided, no pass bar until Track B grades them

Candidate ladder, cheapest first, each a full JudgeBench run (~$10–30):

- **A1 tier & deliberation:** Haiku (current baseline) → Sonnet → Opus, at no-think / low /
  medium effort. §81's spot checks suggest tier moves confidence more than direction; measure
  it rather than assume it.
- **A2 protocol:** (i) tie-licensed forced choice with the B3 calibration reading; (ii)
  notice-then-judge two-stage (describe the difference before preferring — worded to avoid the
  diff-spotting frame `pair_turn` already documents); (iii) small **diverse ensembles** — 3
  judges differing in model or persona, majority-aggregated; diversity is a positional
  debiaser no single judge can be; (iv) whole-scene vs excerpt context.
- **A3 dimension coverage:** the affect column — the valence/arousal trajectory model from the
  emotion-dataset thread — admitted only if it survives its own refutation gauntlet
  (acclaimed-prose control, lexicon-redundancy check, conversion separation). It would be the
  panel's first instrument for the "flat" defect that isn't a word list.

**Deliverable and freeze rule.** Track A ends by freezing **panel v2** — one model, protocol,
and aggregation, chosen on JudgeBench and recorded in the ledger — *before* Track B is funded.
The batch's agreement analysis is pre-registered against v2, and no judge is re-selected after
human numbers arrive. Judge shopping against the anchor is the forking path this rule exists
to close.

## 5. Licences — what "as good as human judgment" concretely means

- **L1 — compliance certification.** Deterministic checks certify that a revision changed
  exactly one named thing. Already earned; no panel or human required.
- **L2 — selection between candidates on axis X.** Earned per axis when the batch shows
  panel-human agreement in direction, with the human lower bound clear of 0.5 and the panel's
  interval excluding 0.5 on that axis. This is the licence the book loop actually needs:
  choose between discriminable variants on anchored axes.
- **L3 — in-loop drafting feedback.** L2 plus a monthly micro-probe (~$50 of human judgments
  on fresh pairs) whose failure revokes the axis. §72's expires-on-use rule governs.
- **Never licensed:** absolute headline claims ("beats human prose") without fresh human data
  under §61's declared frame. No agreement matrix makes the panel a substitute there.

## 6. Sequencing

1. **Now, machine-only (~$50–100 total):** land the repair run (in flight); build the
   JudgeBench harness from existing fixtures; run the A1/A2 ladder; freeze panel v2 in a
   ledger entry.
2. **Operator gate:** fund the batch. Fund it only when v2 is frozen *and* the book pipeline
   is ready to consume L2 within the month the §59 clock allows.
3. **After the batch:** agreement matrix → licence assignment (pre-registered rule, §5) →
   the book-improvement loop runs on machine judgments where licensed, with monthly probes.
4. **Fallback if Track A fails (§7):** the book work proceeds anyway — repairs certified by
   L1, selection by operator read (§74's channel, the most productive instrument this project
   has had), panel demoted to compliance-checking. The program degrades to "humans judge,
   machines certify," which is where it already stands today.

## 7. Kill conditions and rails

- **Program-level kill:** no Track-A candidate clears B4 at 0.52 across strata with clean
  bias. Then machine taste is unavailable at the current frontier, the anchor money buys only
  the headline pilot, and the fallback in §6.4 is the plan.
- §82's rule stands verbatim: no machine-only result upgrades any licence.
- Every fixture bar in §3 is fixed before the first candidate runs; thresholds carry
  intervals per §81's lesson; no bar moves after numbers arrive.
- One cache file per concurrent run, digest-keyed, per RUNBOOK.
